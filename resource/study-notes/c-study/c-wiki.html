C 语言学习指南 Wiki

系统化 C 语言参考 · 从基础语法到指针与内存管理

学习路线图 ROADMAP

以下路线面向零基础到进阶，总周期约 8–12 周。C 语言的核心难点集中在指针、内存管理与数组/字符串的边界问题，建议在这三块上多花时间动手调试。

阶段 0 · 环境准备

0.5–1 天

安装编译器（GCC/Clang/MSVC）与编辑器，能完成“编辑 → 编译 → 运行”的闭环。理解 gcc main.c -o main 的含义，能读懂编译错误信息。

阶段 1 · 语法入门

2–3 周

数据类型、变量与常量、运算符、if/switch/for/while 流程控制、函数定义与调用。关键产出：计算器、猜数字、九九乘法表、简易菜单程序。重点理解：整型溢出、浮点精度、% 取模规则。

阶段 2 · 数组与字符串

1–2 周

一维/二维数组、C 风格字符串（以 '\0' 结尾）、string.h 常用函数、数组越界与缓冲区溢出。关键产出：冒泡排序、字符串反转、单词计数。

阶段 3 · 指针与内存

2–3 周

指针概念、指针与数组的关系、指针作为函数参数（实现“传引用”）、函数指针、malloc/free 动态内存、栈与堆的区别。这是 C 语言的分水岭，建议配合调试器观察地址与内存布局。关键产出：动态数组、链表、简单的内存池。

阶段 4 · 复合类型与模块化

1–2 周

结构体、联合体、枚举、typedef、多文件编译、头文件与 static/extern 链接属性。关键产出：用结构体实现学生成绩管理系统，拆分为 .h/.c 多文件。

阶段 5 · 进阶与实战

2–4 周

文件 I/O、预处理宏、位运算、可变参数、简单数据结构（链表/栈/队列/哈希表）。实战项目：命令行通讯录、简易文本编辑器、基于链表的任务队列。若继续深入，可学习 POSIX 系统调用与网络编程。

程序结构与编译流程 BASICS

最小程序

#include <stdio.h>   // 预处理：引入标准输入输出头文件

int main(void) {
    printf("Hello, World!\n");
    return 0;          // 返回 0 表示正常退出
}

编译流程（四个阶段）

阶段命令示意产物说明
预处理gcc -E main.c -o main.i.i展开 #include、#define，处理条件编译，删除注释。
编译gcc -S main.i -o main.s.s将 C 代码翻译为汇编代码，进行语法与语义检查。
汇编gcc -c main.s -o main.o.o将汇编代码翻译为机器码（目标文件），符号尚未解析。
链接gcc main.o -o main可执行文件将目标文件与库（如 libc）合并，解析外部符号，生成最终可执行文件。
常见编译选项：-Wall -Wextra 开启更多警告；-g 生成调试信息；-O2 优化；-std=c11 指定标准；-lm 链接数学库（使用 math.h 时需要）。

修饰符与常量

  • signed / unsigned：指定符号性。无符号整型表示非负数，溢出为模运算。
  • const：只读限定，修饰变量后不可修改。
  • volatile：告诉编译器该变量可能被外部改变，禁止优化掉访问（嵌入式/信号处理常用）。
  • 整型常量：十进制 42、八进制 052、十六进制 0x2A、二进制（C23）0b101010。
  • 字符常量：'A'；转义：'\n'、'\t'、'\\'、'\0'。
  • 浮点常量：3.14、1e-9、1.0f（float 后缀）。
整型溢出：有符号整型溢出是未定义行为（UB），无符号整型溢出按 2^n 取模。不要依赖溢出行为编写逻辑。比较有符号与无符号数时，有符号数会被转换为无符号，可能导致意外结果（如 -1 > 0u 为真）。

流程控制 CONTROL

分支

// if-else if-else
if (score >= 90)       printf("A\n");
else if (score >= 60)  printf("B\n");
else                   printf("C\n");

// switch：表达式必须是整型/枚举
switch (choice) {
    case 1: puts("新建"); break;
    case 2: puts("打开"); break;
    default: puts("无效"); break;
}
// 漏写 break 会导致“贯穿（fall-through）”，有时有意为之（如多个 case 共享逻辑）

循环

// for：已知迭代次数
for (int i = 0; i < 10; ++i)
    printf("%d ", i);

// while：条件驱动
int n = 5;
while (n > 0) { printf("%d\n", n--); }

// do-while：至少执行一次
int input;
do {
    scanf("%d", &input);
} while (input < 0);   // 确保输入非负

// break / continue
for (int i = 0; i < 100; ++i) {
    if (i % 2 == 0) continue;  // 跳过偶数
    if (i > 10) break;         // 超过 10 退出
}
常见错误：for 循环头中写 for (int i = 0; i < n; i++); 多了一个分号——循环体为空，后续语句只执行一次。while 条件中误用 = 而非 ==。

定义、声明与调用

int main(void) {

}

参数传递：值传递 vs 指针传递

C 语言只有值传递。要“修改实参”，必须传入地址（指针），在函数内通过解引用修改。

// ❌ 值传递：修改的是副本
void bad_swap(int a, int b) {
    int t = a; a = b; b = t;   // 不影响外部
}

// ✅ 指针传递：通过地址修改原变量
void swap(int *a, int *b) {
    int t = *a; *a = *b; *b = t;
}
// 调用：swap(&x, &y);

函数指针

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

// 声明函数指针
int (*op)(int, int);

op = add;
printf("%d\n", op(2, 3));  // 5
op = mul;
printf("%d\n", op(2, 3));  // 6

递归

int factorial(int n) {
    if (n <= 1) return 1;      // 终止条件
    return n * factorial(n - 1);
}
递归要点：必须有明确的终止条件；递归深度过大会导致栈溢出。C 语言没有尾调用优化保证，深度递归建议改为迭代。

指针基础 POINTERS

指针是存储内存地址的变量。理解指针是掌握 C 语言的关键。

基本操作

int x = 42;
int *p = &x;      // p 保存 x 的地址

printf("%d\n", *p);   // 解引用：输出 42
*p = 100;            // 通过指针修改 x
printf("%d\n", x);   // 100

int **pp = &p;     // 指向指针的指针
printf("%d\n", **pp);  // 42

指针与数组

数组名在大多数表达式中退化为指向首元素的指针。a[i] 等价于 *(a + i)。

int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;          // 等价于 &arr[0]
printf("%d\n", *(p + 2));   // 30，等价于 arr[2]
printf("%d\n", p[3]);        // 40，指针也支持下标

// 指针遍历数组
for (int *q = arr; q < arr + 5; ++q)
    printf("%d ", *q);

int * const p常量指针（指针本身不可改）不可以可以

NULL 与空指针

int *p = NULL;        // 传统写法，NULL 通常是 ((void*)0) 或 0
if (p != NULL) { /* 使用前判空 */ }

// 解引用空指针是未定义行为（通常导致段错误）
// *p;  // ❌ 崩溃
三大指针错误：① 解引用空指针；② 解引用未初始化的野指针；③ 指针越界访问（指向数组范围之外）。C 语言不会自动检查这些错误，必须靠编码纪律与工具（AddressSanitizer/Valgrind）发现。

动态内存管理 MEMORY

栈内存由编译器自动管理，大小有限；堆内存由程序员手动申请与释放，生命周期可控。#include <stdlib.h>。

函数功能说明
malloc(size)分配 size 字节返回 void*，未初始化；失败返回 NULL
calloc(n, size)分配 n * size 字节并清零适合数组；失败返回 NULL
realloc(p, new_size)调整已分配内存大小可能移动内存并返回新地址；失败返回 NULL，原内存仍有效
free(p)释放 p 指向的内存只能释放 malloc/calloc/realloc 返回的指针；free(NULL) 安全

典型用法

// 动态数组
int n = 10;
int *arr = (int*)malloc(n * sizeof(int));
if (arr == NULL) {
    fprintf(stderr, "内存分配失败\n");
    return 1;
}
for (int i = 0; i < n; ++i) arr[i] = i * i;

free(arr);
arr = NULL;          // 避免悬空指针

// 扩容
int *tmp = (int*)realloc(arr, 2 * n * sizeof(int));
if (tmp != NULL) {
    arr = tmp;             // 仅在成功时更新指针，避免泄漏
}
realloc 陷阱：不要写成 arr = realloc(arr, ...)。若 realloc 失败返回 NULL，原指针就丢失了，造成内存泄漏。应先用临时指针接收返回值，成功后再赋值。
常见内存错误：
  • 内存泄漏：malloc 后忘记 free。
  • 双重释放：同一指针 free 两次。
  • 悬空指针：free 后继续使用该指针。
  • 越界写：分配 n 字节却写入 n+1 字节。
  • 释放非堆指针：对栈变量或数组名调用 free。

字符串是以 '\0' 结尾的字符数组。这个结尾符是字符串函数正确工作的前提。

char s1[] = "hello";         // 自动加 '\0'，长度 6

// 字符数组逐字符初始化（注意手动加结束符）

string.h 常用函数

函数功能注意
strlen(s)返回字符串长度（不含 '\0'）O(n)；要求 s 以 '\0' 结尾
strcpy(dst, src)复制字符串（含 '\0'）不检查 dst 容量，易溢出；优先用 strncpy
strncpy(dst, src, n)最多复制 n 个字符若 src 长度 ≥ n，不会自动补 '\0'，需手动设置
strcat(dst, src)将 src 追加到 dst 末尾不检查容量；优先用 strncat
strcmp(a, b)比较字符串相等返回 0；a<b 返回负；a>b 返回正
strncmp(a, b, n)比较前 n 个字符常用于前缀判断
strchr(s, c)查找字符 c 首次出现位置返回指针，未找到返回 NULL
strstr(s, sub)查找子串返回首次出现位置指针，未找到返回 NULL
strtok(s, delim)按分隔符切分字符串会修改原字符串；非线程安全；首次传 s，后续传 NULL
memcpy(dst, src, n)复制 n 字节内存源与目标不可重叠；重叠用 memmove
memmove(dst, src, n)复制 n 字节内存（支持重叠）稍慢但安全
memset(p, value, n)将 n 字节设置为 value常用于清零；对 int 数组设置为 0 才安全
memcmp(a, b, n)比较 n 字节内存返回 0 表示相同
缓冲区溢出：strcpy/strcat/sprintf 都不检查目标缓冲区容量，是安全漏洞的常见来源。优先使用带长度限制的版本（strncpy、strncat、snprintf），并确保目标缓冲区足够大且以 '\0' 结尾。

结构体与联合体 STRUCT

结构体

struct Student {
    char name[32];
    int age;
    float score;
};

struct Student s1 = {"Alice", 20, 92.5f};
struct Student s2;
strcpy(s2.name, "Bob");
s2.age = 21;
s2.score = 88.0f;

// 指针访问成员使用 ->
struct Student *p = &s1;
printf("%s, %d\n", p->name, p->age);

// 结构体数组
struct Student cls[2] = {
    {"Alice", 20, 92.5f},
    {"Bob", 21, 88.0f}

内存对齐与 sizeof

结构体成员之间可能存在填充字节（padding），以满足对齐要求。sizeof(struct) 可能大于各成员大小之和。

struct A {
    char c;     // 1 字节
    int i;      // 4 字节，前面通常填充 3 字节
    char d;     // 1 字节，后面可能填充 3 字节
};
// sizeof(struct A) 常为 12（而非 6）

// 调整成员顺序可减少填充：
struct B {
    int i;      // 4
    char c;     // 1
    char d;     // 1（+2 填充）
};
// sizeof(struct B) 常为 8

联合体（union）

所有成员共享同一块内存，大小等于最大成员的大小。同一时刻只能有效使用一个成员。

union Value {
    int i;
    float f;
    char bytes[4];
};  // sizeof 通常为 4

union Value v;
v.i = 0x3f800000;
// 此时读取 v.f 是“类型双关”，C 标准对读取非活跃成员的行为有争议，
// 严谨做法是使用 memcpy 或通过 bytes 观察字节表示。
结构体 vs 联合体：结构体成员各占独立内存，可同时使用；联合体成员共享内存，节省空间但同一时刻只能有效使用一个。联合体常用于实现变体类型、协议解析与内存节省。

枚举

typedef enum {
    COLOR_RED,      // 默认 0
    COLOR_GREEN,    // 1
    COLOR_BLUE      // 2
} Color;

// 显式赋值
typedef enum {
    STATUS_OK = 0,
    STATUS_ERR = -1,
    STATUS_BUSY = 1
} Status;
枚举的本质：枚举常量是 int 类型（C 标准中），可以参与整型运算。用枚举代替魔法数字，可显著提升代码可读性。C23 起支持指定底层类型（enum E : unsigned char）。

stdio.h 输入输出 STDIO

#include <stdio.h>

函数功能要点
printf(fmt, ...)格式化输出到 stdout返回输出字符数，出错返回负值
fprintf(stream, fmt, ...)格式化输出到指定流错误信息建议输出到 stderr
sprintf(buf, fmt, ...)格式化输出到字符串不检查 buf 容量，推荐 snprintf
snprintf(buf, n, fmt, ...)格式化输出到字符串，最多写 n-1 个字符总是以 '\0' 结尾；返回“本应写入”的长度，可用于检测截断
scanf(fmt, ...)从 stdin 格式化读取参数必须是地址；返回值是成功读取的项数

getchar()读取一个字符返回 int（可能为 EOF）

fgets(buf, n, stream)读取一行（最多 n-1 字符）保留换行符；比 gets 安全（gets 已从 C11 移除）
fputs(s, stream)输出字符串不自动加换行

qsort 比较函数

// 升序比较 int
int cmp_int(const void *a, const void *b) {
    int x = *(const int*)a;
    int y = *(const int*)b;
    return (x > y) - (x < y);   // 避免减法溢出，返回 -1/0/1
}

int arr[] = {5, 2, 8, 1, 9};
size_t n = sizeof(arr) / sizeof(arr[0]);
qsort(arr, n, sizeof(int), cmp_int);
比较函数返回值：应返回负值（a 在前）、0（相等）、正值（b 在前）。直接写 return x - y; 在极端值下可能整型溢出，推荐用 (x > y) - (x < y) 的写法。

string.h 字符串处理 STRING

#include <string.h> · 函数清单已在“数组与字符串”章节列出，此处补充典型用法。

安全复制与拼接

char dst[16];
const char *src = "hello";

// strncpy：最多复制 n 个字符，但不保证 '\0'
strncpy(dst, src, sizeof(dst) - 1);
dst[sizeof(dst) - 1] = '\0';   // 手动保证结尾

// snprintf 更直观：最多写入 size-1 个字符并保证 '\0'
snprintf(dst, sizeof(dst), "%s", src);

strtok 切分字符串

char line[] = "apple,banana,cherry";
char *token = strtok(line, ",");
while (token != NULL) {
    printf("%s\n", token);
    token = strtok(NULL, ",");   // 后续传 NULL
}
strtok 的副作用：它会就地修改原字符串（将分隔符替换为 '\0'），因此不能用于字符串字面量或 const 字符串。它使用内部静态状态，不可重入、非线程安全。多线程或需要保留原串时，使用 strtok_r（POSIX）或手动解析。

常见陷阱与避坑指南 PITFALLS

1. 数组越界与缓冲区溢出

高频

// ❌ 经典越界：i <= 10 访问 arr[10]，合法下标是 0~9
int arr[10];
for (int i = 0; i <= 10; ++i) arr[i] = i;

// ❌ 缓冲区溢出
char buf[8];
strcpy(buf, "this is too long");   // 溢出

// ✅ 使用 snprintf 与边界检查
snprintf(buf, sizeof(buf), "%s", "safe");

对策：循环边界用 < 而非 <=；所有写入缓冲区的操作都要检查容量；编译时开启 -fsanitize=address 运行测试。

2. 忘记初始化

// ❌ 局部变量未初始化，值不确定
int sum;
for (int i = 0; i < 10; ++i) sum += i;   // UB

// ✅ 声明即初始化
int sum = 0;

对策：变量声明时立即初始化；结构体用 = {0} 清零；数组用 = {0}。编译器 -Wuninitialized（含于 -Wall）可发现部分问题。

3. 指针与内存错误

// ❌ 悬空指针
int *p = (int*)malloc(sizeof(int));
free(p);
// *p = 10;  // 未定义行为

// ❌ 内存泄漏
int *q = (int*)malloc(100 * sizeof(int));
q = NULL;   // 原地址丢失，泄漏

// ✅ free 后置空；realloc 用临时指针
free(p);
p = NULL;

对策：free 后立即将指针置 NULL；每对 malloc 都要有配对的 free，并让申请与释放尽量靠近同一作用域；使用 Valgrind/ASan 检测。

4. 字符串与字符数组混淆

// ❌ 没有 '\0' 结尾，strlen/printf 越界读取
char s[3] = {'a', 'b', 'c'};
printf("%s", s);   // 行为未定义

// ✅ 留出结束符空间
char s2[4] = {'a', 'b', 'c', '\0'};

对策：字符数组用于字符串时必须确保有 '\0'；使用 strncpy 后手动补 '\0'；优先用 snprintf 构造字符串。

5. 有符号与无符号混用

// ❌ 无符号数“看起来”永远大于等于 0
unsigned int u = 1;
int i = -1;
if (i < u) { /* 实际为假：i 被转换为无符号的大数 */ }

// ❌ 倒序循环的经典错误
for (unsigned int k = 10; k >= 0; --k) { /* 死循环 */ }

对策：避免有符号与无符号混用；循环计数尽量用 int 或 size_t 并注意方向；编译时开启 -Wsign-compare。

6. 函数返回值未检查

// ❌ 未检查 fopen / malloc / scanf 的返回值
FILE *fp = fopen("data.txt", "r");
// 若文件不存在，fp 为 NULL，后续 fscanf 崩溃

// ✅ 检查
if (fp == NULL) {
    perror("fopen");
    return 1;
}

对策：所有可能失败的标准库函数（fopen、malloc、scanf、fread 等）都应检查返回值，并给出错误处理。

编码规范核心要点 STYLE

以下要点提炼自常见 C 编码规范（Linux 内核风格、Google C 风格等），原则是一致性优先，团队内统一即可。

命名约定

  • 变量/函数：小写 + 下划线，如 max_count、compute_sum()（Linux 风格）；或大驼峰（Windows 风格），保持全项目一致。
  • 宏/常量：全大写 + 下划线，如 MAX_BUFFER_SIZE。
  • 类型名：加 _t 后缀或大驼峰，如 size_t、Student。
  • 名字要有描述性，避免 a、b、tmp（极短作用域除外）。

头文件与模块化

  • 头文件必须使用 #ifndef / #define / #endif 保护宏（或 #pragma once）。
  • 头文件中只放声明，定义（函数体、全局变量）放在 .c 文件。
  • 内部函数用 static 限制链接属性，避免命名冲突。
  • 头文件包含顺序：自身头文件 → 系统头 → 项目头。

指针与内存

  • 指针声明时尽量初始化（NULL 或有效地址）。
  • free 后立即置 NULL。
  • malloc 的返回值必须检查。
  • 申请与释放放在同一函数或同一模块中，遵循“谁申请谁释放”原则。
  • 用 const 修饰不修改的指针参数。

可读性

  • 用 #define 或 const 代替魔法数字。
  • 复杂表达式加括号，不依赖优先级记忆。
  • 函数保持短小，单一职责；参数不超过 5~6 个。
  • 用 goto 集中清理资源是少数被接受的用法（如 Linux 内核），但不要滥用。
  • 注释解释“为什么”，而不是“做什么”。

预处理

  • 宏参数和整体都要加括号：#define SQUARE(x) ((x) * (x))。
  • 避免带副作用的宏参数（如 SQUARE(i++)）。
  • 能用 static inline 函数替代宏时优先用函数（有类型检查）。
  • 调试用 #ifdef DEBUG 隔离。

编译与警告

  • 始终开启 -Wall -Wextra，把警告当错误（-Werror）来对待。
  • 固定 C 标准：-std=c11 或 -std=c17，避免依赖编译器扩展。
  • 使用 -fsanitize=address,undefined 在测试阶段发现内存与 UB 问题。
  • CI 中集成静态分析（cppcheck/clang-tidy）。
