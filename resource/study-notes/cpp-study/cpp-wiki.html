学习路线图 ROADMAP

以下路线基于现代 C++ 学习共识整理，总周期约 12–20 周（视基础与投入时间而定）。每个阶段均有明确的产出目标与检验标准。

阶段 0 · 环境准备

0.5–1 天

完成编译器与编辑器搭建，能编译运行第一个 Hello, World!。Windows 推荐 MinGW-w64/MSVC + VS Code；Mac 使用 Xcode Command Line Tools；Linux 使用 GCC/Clang。

阶段 1 · 入门基础

2–3 周

掌握变量与数据类型、运算符、流程控制（if/for/while）、函数（定义/调用/参数传递）、数组与字符串。理解编译链接流程、头文件保护宏、指针与引用的基本区别。关键产出：控制台计算器、猜数字游戏、简易通讯录（数组版）。常见坑：变量未初始化、数组越界、野指针。

阶段 2 · 面向对象核心

3–4 周

类与对象、封装与访问控制、构造函数/析构函数；拷贝构造与赋值运算符重载（深拷贝 vs 浅拷贝）；继承与多态（虚函数、vtable 概念）；static 成员、友元、模板基础。关键产出：设计一个具备继承体系的班级/图书管理系统。

阶段 3 · 现代 C++ 与 STL

2–3 周

STL 容器（vector、map、set、unordered_map 等）与算法（sort、find、accumulate、lower_bound 等）；迭代器概念与失效规则；智能指针（unique_ptr、shared_ptr）；移动语义与 std::move。关键产出：使用 STL 重构通讯录，用 map 做词频统计，用 sort + 自定义比较器排序。

阶段 4 · 系统与实战

4–6 周

RAII 原则、异常安全、文件 I/O、多线程基础（std::thread、mutex）、CMake 构建多文件项目。实战项目建议：简易 HTTP 服务器、命令行任务管理器、基于 STL 的日志分析工具。

阶段 5 · 面试冲刺（可选）

2–3 周

高频考点：虚函数底层机制、智能指针实现原理、STL 容器底层数据结构与复杂度、迭代器失效场景、移动语义与完美转发、C++11/14/17 关键新特性。刷题以 LeetCode STL 相关题目为主，侧重边界条件与复杂度分析。

STL 容器分类概览 CONTAINERS

STL 容器主要分为四大类，理解分类是选择正确容器的前提。

类别典型容器底层结构特点与适用场景
序列式容器 vector、deque、list 动态数组 / 分块数组 / 双向链表 按插入顺序存储。vector 随机访问最快；deque 首尾插入高效；list 任意位置插入/删除 O(1)，但不支持随机访问。
关联式容器 set、map、multiset、multimap 红黑树 元素按键自动排序，查找/插入/删除 O(log n)。需要有序遍历或范围查询时使用。
无序关联式容器 unordered_set、unordered_map 哈希表 平均 O(1) 查找，不保证顺序。追求平均性能、对顺序无要求时的首选。
容器适配器 stack、queue、priority_queue 封装 deque / vector 等 提供受限接口。stack 后进先出；queue 先进先出；priority_queue 按优先级出队（默认大顶堆）。
选择原则：默认 vector；需要按键快速查找用 unordered_map；需要有序键用 map；需要去重且有序用 set；频繁在中间插入/删除且不需随机访问时考虑 list。

vector（动态数组） SEQUENCE

#include <vector> · 连续内存 · 随机访问 O(1) · 尾部插入/删除均摊 O(1)。

常用成员函数

函数功能注意
push_back(x)尾部插入元素 x可能触发扩容，使所有迭代器/指针/引用失效
pop_back()删除尾部元素容器为空时行为未定义
size()当前元素个数与 capacity() 区分：size 是实际元素数，capacity 是已分配内存可容纳的元素数
capacity()当前分配的存储容量通常 ≥ size，扩容策略因实现而异（常见 1.5 或 2 倍）
reserve(n)预分配至少容纳 n 个元素的内存只改变 capacity，不改变 size；避免频繁扩容的有效手段
resize(n)将 size 调整为 nn > size 时填充默认值；n < size 时截断
at(i)访问下标 i 的元素，越界抛出 std::out_of_range比 operator[] 安全，但有轻微开销
operator[](i)访问下标 i 的元素不检查越界，越界行为未定义
front() / back()首元素 / 尾元素引用容器为空时调用未定义
begin() / end()正向迭代器cbegin() / cend() 返回只读迭代器（C++11）
erase(p)删除迭代器 p 指向的元素使被删除位置及之后的所有迭代器/引用失效；返回下一个有效迭代器
insert(p, x)在 p 之前插入 x可能使所有迭代器失效（若触发扩容）
clear()清空所有元素size 变为 0，capacity 通常不变
shrink_to_fit()请求将 capacity 降至 size非强制性，实现可以忽略

典型代码

// 预分配 + 范围 for
std::vector<int> v;
v.reserve(100);          // 避免中途扩容
for (int i = 0; i < 100; ++i) v.push_back(i);

for (const auto& x : v) {        // 只读遍历，避免拷贝
    std::cout << x << ' ';
}

// 删除所有偶数（正确方式）
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) it = v.erase(it);
    else ++it;
}
迭代器失效：插入操作若触发扩容会使所有迭代器失效；erase 使被删除位置及之后的所有迭代器失效。循环中删除元素时，务必使用 it = v.erase(it) 的写法，而不是 v.erase(it); ++it;。

deque 与 list SEQUENCE

deque（双端队列）

#include <deque> · 分块连续内存 · 随机访问 O(1) · 首尾插入/删除 O(1)。

函数功能与 vector 的差异
push_front(x)头部插入vector 没有此操作
pop_front()头部删除vector 没有此操作
push_back / pop_back尾部操作与 vector 相同
operator[] / at随机访问访问效率略低于 vector（多一层间接）

适用场景：需要在两端频繁插入/删除，同时仍需要随机访问元素时（如滑动窗口、双端队列式任务调度）。

list（双向链表）

#include <list> · 非连续内存 · 不支持随机访问 · 任意位置插入/删除 O(1)。

函数功能注意
push_front / pop_front头部操作O(1)
insert(p, x)在 p 之前插入O(1)，不使其他迭代器失效
erase(p)删除 p 处元素O(1)，仅使被删除元素的迭代器失效
splice(p, other, q)将 other 中 q 处的节点“剪切”到 p 之前O(1)，不拷贝/移动元素，仅调整指针
sort()成员排序list 不支持随机访问迭代器，不能用 std::sort，需使用成员 sort()
remove(x)删除所有值为 x 的元素与 std::remove 不同，list 的成员版本真正删除节点
list 的独特优势：splice 可以在 O(1) 时间内将节点从一个 list 移动到另一个 list，不涉及元素拷贝，适合需要频繁重组链表的场景。

map 与 set ASSOCIATIVE

map（有序键值对）

#include <map> · 红黑树 · 键唯一且自动排序 · 查找/插入/删除 O(log n)[reference:8]。

函数 / 操作功能注意
operator[](key)访问 key 对应的值若 key 不存在，会插入默认值并返回引用；只想查找时应用 find
at(key)访问 key 对应的值key 不存在时抛出 std::out_of_range，比 [] 安全
insert({key, val})插入键值对若 key 已存在则不插入（map 不覆盖），返回 pair<iterator, bool>
find(key)查找 key找到返回迭代器，否则返回 end()。判断存在应使用 m.find(k) != m.end()
count(key)返回 key 的出现次数对 map 而言是 0 或 1（multimap 可大于 1）
erase(key)删除指定 key返回删除的元素个数（map 中为 0 或 1）
lower_bound(key)第一个键 ≥ key 的迭代器有序范围查询的基础
upper_bound(key)第一个键 > key 的迭代器配合 lower_bound 可获取等于 key 的区间

set（有序集合）

#include <set> · 红黑树 · 元素唯一且自动排序 · 操作 O(log n)[reference:9]。

函数功能注意
insert(x)插入元素 x若 x 已存在则不插入；返回 pair<iterator, bool>
erase(x)删除值为 x 的元素返回删除个数（set 中为 0 或 1）
find(x)查找 x未找到返回 end()
count(x)返回 x 的个数set 中为 0 或 1
lower_bound / upper_bound范围查询与 map 类似

unordered_map / unordered_set

#include <unordered_map> / #include <unordered_set> · 哈希表 · 平均 O(1) 查找，不保证顺序[reference:10]。

选择建议：需要有序遍历键 → map/set；只关心快速查找、对顺序无要求 → unordered_map/unordered_set。最坏情况下哈希表可能退化到 O(n)，但实际使用中平均性能通常显著优于红黑树。

常用 STL 算法速查 ALGORITHMS

STL 提供约 100 个算法模板函数，大部分位于 <algorithm>，数值算法在 <numeric>[reference:11]。

算法头文件功能时间复杂度
sort(begin, end, cmp)<algorithm>对区间排序（默认升序，可传自定义比较器）O(n log n)
stable_sort<algorithm>稳定排序，相等元素保持原有相对顺序O(n log n)（可能额外内存）
find(begin, end, val)<algorithm>顺序查找第一个等于 val 的元素，返回迭代器O(n)
find_if(begin, end, pred)<algorithm>查找第一个满足谓词的元素O(n)
count(begin, end, val)<algorithm>统计等于 val 的元素个数O(n)
count_if(begin, end, pred)<algorithm>统计满足谓词的元素个数O(n)
reverse(begin, end)<algorithm>翻转区间O(n)
unique(begin, end)<algorithm>去除相邻重复元素，返回去重后尾迭代器；需先排序才能全局去重O(n)
binary_search(begin, end, val)<algorithm>在有序区间中二分查找，返回 boolO(log n)
lower_bound(begin, end, val)<algorithm>第一个 ≥ val 的元素位置O(log n)
upper_bound(begin, end, val)<algorithm>第一个 > val 的元素位置O(log n)
merge(b1, e1, b2, e2, out)<algorithm>合并两个有序区间到输出迭代器O(n+m)
accumulate(begin, end, init)<numeric>对区间元素求和（可传自定义二元操作）O(n)
max_element / min_element<algorithm>返回区间中最大/最小元素的迭代器O(n)
transform(begin, end, out, op)<algorithm>对每个元素应用 op 并写入 outO(n)
for_each(begin, end, fn)<algorithm>对每个元素调用 fnO(n)
注意：std::sort 要求随机访问迭代器，因此 list 不能使用 std::sort，应使用成员函数 list::sort()。binary_search、lower_bound、upper_bound 要求区间已有序。

典型算法用法示例 EXAMPLES

sort + 自定义比较器

std::vector<std::pair<std::string, int>> items = {{"b", 2}, {"a", 3}, {"c", 1}};

// 按 second 降序排列
std::sort(items.begin(), items.end(),
    [](const auto& a, const auto& b) {
        return a.second > b.second;
    });

去重（sort + unique + erase）

std::vector<int> v = {3, 1, 2, 3, 2, 1};
std::sort(v.begin(), v.end());          // 先排序：1 1 2 2 3 3
auto last = std::unique(v.begin(), v.end()); // 相邻去重
v.erase(last, v.end());              // 真正删除尾部冗余元素
// v 现在为 {1, 2, 3}

accumulate 求和与自定义操作

// 求和
std::vector<int> nums = {1, 2, 3, 4, 5};
int sum = std::accumulate(nums.begin(), nums.end(), 0); // 15

// 求乘积（使用自定义二元操作）
int product = std::accumulate(nums.begin(), nums.end(), 1,
    [](int a, int b) { return a * b; }); // 120

lower_bound / upper_bound 范围查询

std::vector<int> sorted = {10, 20, 20, 30, 40};
auto lo = std::lower_bound(sorted.begin(), sorted.end(), 20); // 指向第一个 20
auto hi = std::upper_bound(sorted.begin(), sorted.end(), 20); // 指向 30
// 区间 [lo, hi) 包含所有等于 20 的元素
std::cout << "20 的个数: " << (hi - lo) << '\n'; // 2

智能指针 MODERN C++

智能指针是 RAII 原则在资源管理上的核心体现，用对象生命周期自动管理动态分配的内存，从根本上避免内存泄漏与悬空指针[reference:12][reference:13]。

类型所有权语义是否可拷贝开销推荐场景
std::unique_ptr 独占——同一时刻只有一个所有者 不可拷贝，可std::move转移 零额外开销（与裸指针相同） 默认首选。绝大多数动态分配对象应使用 unique_ptr
std::shared_ptr 共享——引用计数归零时释放 可拷贝 控制块 + 原子引用计数，有额外开销 确实需要多个所有者共享同一对象时使用
std::weak_ptr 不增加引用计数的“弱引用” 可拷贝 不控制生命周期 打破 shared_ptr 循环引用；观察者模式中避免悬挂引用

用法对比

// unique_ptr：独占所有权
auto up = std::make_unique<int>(42);
// auto up2 = up;              // ❌ 编译错误：不可拷贝
auto up2 = std::move(up);    // ✅ 所有权转移，up 变为 nullptr

// shared_ptr：共享所有权
auto sp1 = std::make_shared<std::string>("hello");
{
    auto sp2 = sp1;           // 引用计数 2
    // ...
}                               // sp2 析构，引用计数 1
// sp1 仍有效

// weak_ptr：观察 shared_ptr 而不延长生命周期
std::weak_ptr<std::string> wp = sp1;
if (auto locked = wp.lock()) {  // 尝试提升为 shared_ptr
    std::cout << *locked;
}
make 函数优先：优先使用 std::make_unique 和 std::make_shared，而不是 new。它们更安全（避免表达式求值顺序导致泄漏）、更高效（make_shared 一次分配控制块与对象）。

移动语义 MODERN C++

C++11 引入移动语义，允许资源（堆内存、文件句柄等）在对象间“转移”而非拷贝，显著提升性能。

核心规则

  • 右值引用 T&& 绑定到即将销毁的对象（临时对象、std::move 的结果）。
  • 移动构造函数 与 移动赋值运算符 “窃取”源对象的资源，将源对象置于有效但未指定的状态。
  • std::move 本身不移动任何东西，它只是一个类型转换，将左值转为右值引用，从而允许调用移动构造/赋值。
  • 被 std::move 后的对象仍然有效，但不应再依赖其值（标准库容器通常变为空）。
class Buffer {
    int* data_;
    size_t size_;
public:
    // 移动构造函数
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;       // 源对象放弃所有权
        other.size_ = 0;
    }

    // 移动赋值
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }
};
noexcept 的重要性：移动构造函数和移动赋值应标记为 noexcept。否则 std::vector 在扩容时可能放弃移动而改用拷贝，以确保异常安全（强异常保证）。[reference:15]

常见陷阱与避坑指南 PITFALLS

1. 野指针与内存泄漏

高频

// ❌ 野指针：delete 后继续使用
int* p = new int(42);
delete p;
// *p;  // 未定义行为

// ❌ 内存泄漏：new 后忘记 delete
int* q = new int[100];
// ... 没有 delete[] q;

// ✅ 正确：智能指针自动管理
auto sp = std::make_unique<int>(42);

对策：默认使用智能指针；必须使用裸指针时，遵循 RAII，确保每个 new 都有配对的 delete（或 new[] / delete[]），并尽早将所有权移入 RAII 对象[reference:16]。

2. 字符串比较用 == 比较地址

// ❌ 比较的是两个数组的首地址，不是内容
char a[] = "hello";
char b[] = "hello";
if (a == b) { /* 永远为 false */ }

// ✅ 使用 std::string
std::string s1 = "hello", s2 = "hello";
if (s1 == s2) { /* 正确比较内容 */ }

对策：在 C++ 中优先使用 std::string，避免 C 风格字符数组带来的缓冲区溢出和比较陷阱[reference:17]。

3. 对象切片（Object Slicing）

struct Animal { virtual void speak() { std::cout << "Animal\n"; } };
struct Dog : Animal { void speak() override { std::cout << "Woof\n"; } };

void makeSound(Animal a) { a.speak(); }  // ❌ 按值传递，Dog 被切片
void makeSound(Animal& a) { a.speak(); } // ✅ 按引用传递

对策：多态对象通过引用或指针传递，不要按值传递基类对象来接收派生类对象[reference:18]。

4. 浅拷贝导致双重释放

// ❌ 默认拷贝是浅拷贝，两个对象持有同一块堆内存
class Bad {
    int* data;
public:
    Bad() : data(new int(0)) {}
    ~Bad() { delete data; }
};
// Bad b1; Bad b2 = b1;  // 双重 delete

// ✅ 遵循 Rule of Three/Five：自定义析构、拷贝构造、拷贝赋值
// ✅ 或使用智能指针成员，自动获得正确的拷贝/移动语义

对策：管理资源（裸指针、文件句柄等）的类应遵循 Rule of Three/Five：如果需要自定义析构函数，通常也需要自定义拷贝构造函数和拷贝赋值运算符（以及移动版本）。更简单的做法是使用智能指针或标准容器作为成员，让编译器生成的默认操作就是正确的[reference:19]。

5. 容器迭代器失效

// ❌ vector 循环中 erase 后继续使用旧迭代器
for (auto it = v.begin(); it != v.end(); ++it) {
    if (cond) v.erase(it); // it 失效，下一轮 ++it 未定义
}

// ✅ 使用 erase 的返回值
for (auto it = v.begin(); it != v.end(); ) {
    if (cond) it = v.erase(it);
    else ++it;
}

对策：删除元素时使用 it = v.erase(it)；在插入/删除后重新获取迭代器。详情见下一节“迭代器失效规则”。

迭代器失效规则速查 REFERENCE

不同容器在不同操作下的迭代器、指针和引用失效规则不同。使用失效的迭代器是未定义行为，必须严格遵守规则[reference:21]。

容器 插入操作 删除操作 其他
vector 若触发扩容，所有迭代器/指针/引用失效；否则仅插入位置之后的失效 erase(p) 使 p 及之后的所有迭代器/指针/引用失效；pop_back 仅使指向被删元素的失效 reserve/resize 导致扩容时全部失效；clear 全部失效
deque 在首尾插入可能使迭代器失效但引用通常保持有效；在中间插入使所有迭代器/引用失效 在首尾删除仅使指向被删元素的失效；中间删除使全部失效 规则较复杂，保守做法是操作后重新获取
list 插入不使任何迭代器失效 erase(p) 仅使 p 失效，其他不受影响 这是 list 的核心优势之一
map / set 插入不使任何迭代器失效 erase 仅使指向被删元素的迭代器失效 红黑树结构稳定，其余节点不受影响
unordered_map / unordered_set 若触发 rehash（负载因子超限），所有迭代器失效；否则通常不失效 erase 仅使指向被删元素的失效 rehash 可手动触发，使全部失效
铁律：任何可能导致迭代器失效的操作之后，如果还需要继续使用迭代器，必须重新获取（begin()、find() 等），或使用操作返回的新迭代器。不要试图“修补”旧迭代器。

编程规范核心要点 STYLE

以下要点提炼自 Google C++ Style Guide，兼顾可读性、一致性与可维护性。

命名约定

  • 文件名：全小写，用下划线分隔，如 my_class.cc / my_class.h。
  • 类型名：大驼峰，如 MyClass、HttpRequest。
  • 变量名：小写 + 下划线，如 table_name；类成员变量末尾加下划线，如 table_name_。
  • 函数名：大驼峰（Google 风格），如 DoSomething()；访问器可用 get_xxx() / set_xxx()。
  • 常量：k 前缀 + 大驼峰，如 kMaxBufferSize。

头文件

  • 所有头文件必须使用 #define 保护宏，防止重复包含。
  • 保护宏格式：<PROJECT>_<PATH>_<FILE>_H_。
  • 头文件包含顺序：相关头文件 → C 系统头 → C++ 标准库头 → 其他库头 → 项目内头。
  • 尽量使用前向声明替代不必要的 #include，减少编译依赖。

作用域与函数

  • 鼓励使用匿名命名空间或 static 限制内部链接。
  • 仅在函数较小时使用 inline；不要为了“性能”盲目 inline。
  • 函数参数顺序：输入参数在前，输出参数在后。
  • 变量在使用前才声明，并立即初始化。
  • 避免使用全局 using namespace std;，尤其是在头文件中。

类与资源管理

  • 构造函数应轻量，复杂初始化放在 Init() 方法中（Google 建议）。
  • 优先使用 explicit 修饰单参数构造函数，防止意外隐式转换。
  • 资源管理遵循 RAII；优先使用智能指针和标准容器。
  • 能用 unique_ptr 就不用 shared_ptr。
  • 移动操作标记 noexcept。

注释

  • 注释解释 “为什么”，而不是“做什么”（代码本身说明做什么）。
  • 每个类的声明前应有注释说明用途和用法。
  • 对非显而易见的边界条件、所有权转移、线程假设必须注释。
  • 不要保留被注释掉的代码；版本控制会保存历史。

安全与可读性

  • 避免 goto（极少数跳出多层循环的场景除外）。
  • 使用 nullptr 而非 NULL 或 0。
  • 用 const 修饰不修改的变量、参数和成员函数。
  • 用 auto 简化复杂类型声明，但不要滥用导致可读性下降。
  • 优先使用 std::array/std::vector 替代原生数组。
